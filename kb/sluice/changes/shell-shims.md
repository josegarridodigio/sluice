# Change: shell shims (2026-10-23)

Task H5 of [[sluice/plan/alpha-plan.md]]. Design: [[sluice/design/command-control.md]]
section 5 (and 5.1 for the deviations), ADR [[sluice/design/adr/0010-command-control.md]].
Builds on `sluice exec` ([[sluice/changes/command-control-exec.md]]) and the heavy list of the
guard rewrite ([[sluice/changes/guard-rewrite.md]]).

## What changed

- New `sluice shim` subcommand:
  - `install [--dir DIR] [--force]`: one POSIX `sh` wrapper per executable of the heavy list
    into `$XDG_DATA_HOME/sluice/shims` or `~/.local/share/sluice/shims` (dir created 0700,
    wrappers 0755, temporary file + rename). Every wrapper starts with `#!/bin/sh` and
    `# sluice-shim v1` plus a "Generated by Sluice" comment, exports `SLUICE_SHIM_DIR`, and
    execs `<sluice> shim exec <name> -- "$@"` with the absolute path of the installing binary.
    Idempotent (unchanged files are not rewritten); refreshes stale Sluice shims; removes Sluice
    shims of commands no longer listed; refuses (exit 1, names listed) to overwrite a file
    without the header unless `--force`.
  - `uninstall [--dir DIR]`: deletes only regular files that start with the exact header, then
    the directory if it is empty; reports the files it kept. Idempotent.
  - `status [--dir DIR] [--json]`: directory, PATH position, this shell's mode and reason, and per
    shim its state (`current | stale | missing | foreign`), the real binary it resolves to and
    whether it is active (shim dir before the real binary in PATH).
  - hidden `exec <name> -- <args>`: resolves the real binary with
    `which::resolve(name, PATH, cwd, skip_shims = true)` (skips the shim dir canonically, so
    duplicates and symlinks too, and any file carrying the marker); not found → `<name>: command
    not found`, 127. Then `Direct` (exec of the real binary, argv[0] kept) when `SLUICE_JOB` is
    set, `SLUICE_SHIMS` is falsy, no agent is detected and `SLUICE_SHIMS` is not truthy, the
    canonical words do not match the heavy list, or an argument is `-`; otherwise the `sluice
    exec` client in-process with `--label <first two canonical words>` and argv `[real, args]`.
- If the recorded `sluice` binary is gone, the wrapper drops from `PATH` every directory whose
  `<name>` is a Sluice shim and execs `<name>`, so the real command still runs (or the shell
  prints `not found`, 127) without recursion.

## Why

Agents without a hook API (Codex, Cursor, Aider, ...) run heavy commands straight from their
shell and bypass the budget. A `PATH` shim needs no support from the agent; making it inert for
humans and for anything already inside a Sluice job keeps human shells and nested builds exactly
as before.

## Deviations from the design

See [[sluice/design/command-control.md]] 5.1: shell-style not-found message; label = first two
canonical words; shim names derived from the heavy list (`run` → npm/pnpm/yarn/bun, `gradlew`,
`mvnw`, `npx`); fallback strips every dir holding a shim of that name; install prunes; `--dir` on
`status`/`uninstall`; no `doctor` stale-shim check yet (`doctor.rs` was owned by X1 in this
wave); stdin `/dev/null` through the queue.

## Verification

`crates/sluice-gate/tests/shim.rs`:
- `resolution_skips_the_shim_dir_wherever_and_however_it_appears`: shim dir first, in the middle,
  three times, via a symlink, a second shim copy first, nested symlinked copies; human and agent;
  the real `make` calling `make` again.
- `only_shims_in_path_exit_127_like_a_shell_without_recursion`: only shim dirs (plus symlink and a
  second copy) → `sluicefaketool: command not found`, 127, within 10 s, no daemon.
- `wrapper_falls_back_to_the_real_binary_when_sluice_is_gone`.
- `exit_codes_streams_and_binary_output_are_preserved`: 0/1/42/255, separate stdout/stderr bytes,
  256 KiB random binary, in human, agent and `SLUICE_SHIMS=1` sessions.
- `stdin_is_piped_to_direct_runs_and_to_dash_arguments`; `a_terminal_is_kept_in_direct_runs`
  (`script`, skipped if missing).
- `human_sessions_run_the_real_binary_without_contacting_the_daemon` (no socket, no state dir;
  also `SLUICE_SHIMS=0` and `SLUICE_AGENT=0` with `CLAUDECODE=1`).
- `inside_a_job_and_for_light_subcommands_shims_pass_through` (`SLUICE_JOB`, `docker ps`; `docker
  build` queued).
- `agent_sessions_go_through_the_queue_and_show_in_status` (`CLAUDECODE=1` and `SLUICE_SHIMS=1`:
  `status --json` running job `kind: exec`, `label: "make wait"`; child sees `SLUICE_JOB`).
- `ten_concurrent_shimmed_makes_stay_within_the_budget`: budget 4, `exec_weight = 2`, counter file
  and `/proc` peak ≤ 2, 10 runs in `status` totals.
- `install_and_uninstall_are_idempotent_and_leave_foreign_files_alone` (modes, second install
  byte-identical, refusal, `--force`, kept files, pruning, empty dir removed);
  `status_reports_path_order_and_this_shells_mode`.

Dogfooding from the worktree root (`PATH="$HOME/.cargo/bin:$PATH"`): `sluice run fmt`, `sluice
run clippy`, `sluice run test`, results in the task report.
